# W11 · Demo 2 — speculative decoding: ten lines, five tests, then a sweep of the draft length (slides p45–p50)
<!-- 此檔由 bin/publish_demos.py 從 private repo 的 <course>/demos/ 複製而來，請勿在公開 repo 直接編輯。 -->

Speculative decoding lets a small *draft* model write a few tokens ahead and has the large *target* model check all of them in one forward pass. The claim on the slides is that this changes how fast tokens come out and nothing about which tokens come out: with the acceptance rule of Leviathan et al., the output is distributed exactly as the target's own. This demo checks the claim on a toy example where the answer is known, and then measures on real models how much time the trick saves.

## Part (a): the rule, without any model

`speculative_step(p, q, rng)` takes the target's distribution `p` and the draft's distribution `q` over the same tokens and returns one token and a flag saying whether the draft's draw was kept:

1. draw a token `x` from `q`;
2. keep it with probability `min(1, p[x] / q[x])`;
3. otherwise draw again from the *residual* `max(0, p − q)`, normalised.

`speculative_final.py` is the reference (six lines of body); `speculative_live.py` is the same function with an empty body, to be written live. `tests.py` runs five tests on the example of slide p42, $p = (0.5, 0.3, 0.15, 0.05)$ and $q = (0.4, 0.4, 0.1, 0.1)$, with 200,000 draws each:

| Test | What should come out |
|---|---|
| 1 | The share of each token among the outputs equals `p`, within sampling error. |
| 2 | The share of draws that were kept equals $\sum_x \min(p, q) = 0.85$. |
| 3 | A wrong version (`variants.wrong_redraw_step`: after a rejection, redraw from `p` itself) **fails** test 1. Its output is $\min(p, q) + (1 - \beta)\,p = (0.475, 0.345, 0.1225, 0.0575)$. |
| 4 | Another correct rule (`variants.match_only_step`: the target draws its own token; the draft's token counts as kept only if the two agree) passes test 1, and keeps $\sum_x p\,q = 0.34$. |
| 5 | With $p = q$, every draw is kept. |

"Within sampling error" means: for every token, the difference between the observed share and the expected one is at most 4 standard deviations, $4\sqrt{x(1-x)/n}$. With 200,000 draws that is between 0.002 and 0.0045, while the wrong version of test 3 is off by 0.008 to 0.044.

## Part (b): on real models

| | |
|---|---|
| Target | `Qwen/Qwen3-8B` in bf16; a shorter run with `mlx-community/Qwen3-8B-4bit`. |
| Drafts | `Qwen/Qwen3-0.6B` and `Qwen/Qwen3-1.7B` (bf16). All three share one tokenizer. |
| Prompts | `prompts.toml`: 20 asking for code, 20 for English explanatory prose, 20 for Traditional Chinese explanatory prose, and 6 written in Taiwanese with Han characters. All were written for this demo. Chat template with `enable_thinking=False`; up to 160 generated tokens; generation stops at an end-of-sequence token. |
| Grid | draft length $\gamma \in \{1, 2, 3, 4, 6, 8, 12\}$; temperature 0 and 0.6 (plain temperature, no top-p or top-k). |
| Speculative decoding | `mlx-lm`'s `speculative_generate_step`, unchanged. Each round the draft writes $\gamma$ tokens and the target runs once over $\gamma + 1$ positions. |

**The library's acceptance rule is the one of test 4, not the one of tests 1–3.** The target samples its own token at every position, and a draft token is kept if it is the same token. The output is the target's own sample, so the distribution is untouched; but at a temperature above zero fewer drafts survive than under the rejection rule. At temperature 0 both rules reduce to "keep the draft if the two argmaxes agree". `./present.sh inspect` prints the lines of the installed library that implement this.

What is recorded for every cell (one draft, one $\gamma$, one temperature, all prompts):

- **Speed-up**: tokens per second with the draft, divided by tokens per second of the target alone on the same prompts. Both are totals over all prompts (tokens summed, seconds summed). Timing starts when the first round (or the first token) is out, so prompt processing is not counted; the round in which an end-of-sequence token appears and a final round shorter than $\gamma$ are left out.
- **$\alpha$**: drafts kept divided by drafts *actually checked* — the kept ones plus the first rejected one of each round. This is the per-position acceptance probability that the theorem needs. The share of *all* drafted tokens that were kept is a different, smaller number, because the drafts after the first rejection are thrown away unchecked; it equals $(\Omega - 1)/\gamma$ and falls as $\gamma$ grows.
- **$c$**: the draft's time per token divided by the target's, each generating alone on the same prompts.
- **Overlap of the two distributions**: along the text the target generated by itself, both models are run once and $\sum_x \min(p, q)$ and $\sum_x p\,q$ are averaged over positions. The second should be close to the measured $\alpha$; the first is what the rejection rule would have kept.
- **At temperature 0**: whether the speculative output is token for token the same as the target's plain greedy output, and if not, the first position where they differ and how close the target's two best tokens were there.

Three predictions are printed next to each measured speed-up. With $\Omega(\gamma, \alpha) = (1 - \alpha^{\gamma+1})/(1 - \alpha)$:

| Column | Formula | The term for one verification pass |
|---|---|---|
| `Thm 3.8` | $\Omega / (\gamma c + 1)$ | assumed to cost one decode step (Leviathan et al., Theorem 3.8) |
| `+ demo 1` | $\Omega / (\gamma c + r(\gamma + 1))$ | $r(k)$ read off demo 1 (b): the time of a decode step for $k$ sequences divided by that for one, interpolated between the batch sizes measured there |
| `+ verify` | the same | $r(k)$ measured here: the target is fed $k$ tokens at once on a fixed context, $k = 1 \ldots 13$, median of nine |

Every replay prints the caveat: one machine, one family of models, prompts written for this demo, one run per cell; thermal state and background load are not controlled.

## What came out

Rehearsed on 2026-11-27 (MacBook Pro, M5 Max, 64 GB, on mains power; `runs/rehearsal/`). The whole run took 2 hours 25 minutes; peak memory 21 GB.

**(a)** All five tests came out as expected, in 3.3 seconds together. Test 1: largest difference 0.0011 (allowed: 0.0019 to 0.0045). Test 2: 0.8482 kept. Test 3: the wrong version output (0.4752, 0.3439, 0.1233, 0.0577). Test 4: 0.3401 kept.

**(b)** The target alone wrote 31.2 tokens per second.

| Target: Qwen3-8B, bf16 | $c$ | $\alpha$, $T = 0$ | $\alpha$, $T = 0.6$ | best $\gamma$ | speed-up | Theorem 3.8 at that $\gamma$ |
|---|---|---|---|---|---|---|
| draft: Qwen3-0.6B | 0.13 | 0.71 | 0.67 | 4 | 1.73 | 1.87 |
| draft: Qwen3-1.7B | 0.27 | 0.79 | 0.77 | 3 | 1.52 | 1.62 |

(The last three columns are at temperature 0.)

| Qwen3-0.6B, $T = 0$ | $\gamma$ = 1 | 2 | 3 | 4 | 6 | 8 | 12 |
|---|---|---|---|---|---|---|---|
| measured speed-up | 1.44 | 1.68 | 1.73 | 1.73 | 1.47 | 1.30 | 0.91 |
| `Thm 3.8` | 1.50 | 1.75 | 1.84 | 1.87 | 1.79 | 1.64 | 1.37 |
| `+ demo 1` | 1.59 | 1.81 | 1.88 | 1.86 | 1.73 | 1.49 | 1.11 |
| `+ verify` | 1.50 | 1.73 | 1.79 | 1.77 | 0.98 | 1.11 | 0.90 |

- **The cheaper draft won**, although the larger one was kept more often.
- Up to $\gamma = 4$ the measurement is 4–7% below the theorem; a round took 3 to 5 ms longer than the draft steps plus one verification pass.
- From $\gamma = 6$ the theorem is far too optimistic, and at $\gamma = 12$ speculative decoding was slower than the target alone. On this machine one pass over $k$ positions costs as much as a single step for $k \le 5$ (ratio 1.00 to 1.09) and 1.5 to 2.5 times as much for $k = 6 \ldots 13$. The stand-alone timing of that pass is not monotonic between $k = 6$ and $8$ (1.51, 2.47, 1.88), so the `+ verify` column overcorrects at $\gamma = 6$; the cause was not investigated.
- At temperature 0.6 the measured $\alpha$ (0.67 for the 0.6B draft) is close to $\sum p\,q$ (0.69), and $\sum\min(p, q)$ is only 0.72: on these models the match-only rule gives away about three points, far less than on the toy example of part (a).
- The acceptance probability is not the same at every position of a round: it rises from 0.64 for the first drafted token to 0.85 for the twelfth. The number of tokens per round still stays within 3% of $\Omega(\gamma, \alpha)$.

| $\alpha$ at $T = 0$, by kind of prompt | code | English | Traditional Chinese | Taiwanese |
|---|---|---|---|---|
| Qwen3-0.6B | 0.84 | 0.72 | 0.63 | 0.54 |
| Qwen3-1.7B | 0.89 | 0.80 | 0.74 | 0.65 |
| best speed-up, 0.6B (at $\gamma$) | 2.08 (4) | 1.80 (4) | 1.61 (3) | 1.47 (2) |

**At temperature 0 the output was often not identical to plain greedy decoding.** Of 66 generations, 16 were identical token for token at each of $\gamma = 1 \ldots 4$ and 25 or 26 at $\gamma = 6, 8, 12$, with either draft. The first difference came at a median position of 78. At that position the target's two best log-probabilities were exactly equal in 56% of the cases and never more than 0.25 apart; bf16 logits of this magnitude are spaced 0.125 apart, and about 1.5% of all positions are exact ties. Verifying several positions in one pass rounds differently from decoding one token at a time, and a tie then breaks the other way. The results are repeatable; this is a dependence on tensor shape, not randomness.

**With the 4-bit target** (15 prompts, 0.6B draft, temperature 0): alone 77.5 tokens per second, $c = 0.28$; speed-up 1.06, 1.01, 0.88, 0.58 at $\gamma = 1, 2, 4, 8$, where Theorem 3.8 predicts 1.33, 1.40, 1.32, 1.02. Here one pass over two positions already costs 1.21 steps, and `+ demo 1` (1.13, 1.10, 0.90, 0.62) follows the measurement.

**Known weaknesses of this run.** The target alone was 10% slower when measured again at the end, and the baseline was taken only at the start; the cells of the 1.7B draft ran last, so its speed-ups may be understated by up to that much (which would still leave it below the 0.6B draft). One run per cell. Only six Taiwanese prompts, and the language of the output was not checked. The gap between the two best tokens comes from a separate full pass and is itself rounded differently.

## Run it

```bash
cd demos                              # see ../README.md for creating .venv
cd w11_d2_speculative
./present.sh test                     # five tests, the arithmetic, the measuring code on tiny models
./present.sh live --final             # part (a) with the reference implementation, one Enter per test
./present.sh inspect                  # versions, models, tokenizers, the library's acceptance rule
./present.sh probe                    # a few prompts; estimates the time of the full run
./present.sh rehearse --note "on mains power"
./present.sh replay                   # part (b) from the record, four screens
./present.sh show                     # optional: one prompt without and with a draft; kept drafts in green
```

To write part (a) yourself, fill in the body of `speculative_step` in `speculative_live.py` and run `./present.sh live`.

`rehearse` can be interrupted: every finished cell is saved and skipped the next time (`--force` repeats; `--target bf16|q4` and `--part a|base|sweep` run a part). Fewer prompts: `per_kind` in `demo_config.toml`.
