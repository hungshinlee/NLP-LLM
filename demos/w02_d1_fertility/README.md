# W2 · Demo 1 — one set of texts, nine tokenizers (slide p10)

Eight texts go through nine tokenizers and the table on slide p10 is filled in live: token count, tokens per character, bytes per token. Under each row the demo paints the actual segmentation of two of the tokenizers (Qwen3.8 and Mistral) as coloured blocks. Only tokenizers are loaded — no model weights — so the whole thing runs on CPU in a few seconds.

The point is misconception 1 of the course: **a token is not a character and not a word**; it is a byte string that was frequent enough in *that* tokenizer's training data. The same Traditional Chinese paragraph costs 141 tokens on one tokenizer and 468 on another; Simplified and Traditional differ only in glyphs and get different counts; two spellings of the same Tâi-lô sentence (NFC vs. NFD) look identical on screen and tokenize differently; the Hakka character 𠊎 is `[UNK]` on one tokenizer and 3–4 byte tokens on the others.

| Row | Text | What to look at |
|---|---|---|
| `zh_city` | a Traditional Chinese paragraph, 209 characters / 627 bytes (`../w01_d2_bpb/texts/zh_city.txt`) | the anchor row; the four counts on slide p8 come from it |
| `zh_city_en` | the same paragraph in English (`texts/zh_city_en.txt`) | denominator for the cross-language cost |
| `zh_city_hans` | the same paragraph in Simplified Chinese (`texts/zh_city_hans.txt`, regenerated by OpenCC on `rehearse`) | same language, different glyphs, different counts — the bias comes from training data |
| `taigi` | Taiwanese Hokkien in Han characters, 61 characters (`../w01_d2_bpb/texts/taigi.txt`) | contains 𪜶 (U+2A736), four UTF-8 bytes |
| `tailo` | one Tâi-lô sentence, counted twice: NFC and NFD (`texts/tailo.txt`) | identical on screen, different token counts — unless the tokenizer's normalizer applies NFC |
| `hakka` | one Hakka sentence with two 𠊎 (`texts/hakka.txt`) | `[UNK]` on bert-base-chinese; 3–4 tokens elsewhere |
| `python` | eight lines of Python — W2 demo 2's `get_pairs` (`texts/python.txt`) | how indentation and whitespace are split |
| `numbers` | `3.14159265358979` and `1234567` (inline) | the pre-tokenizer's digit rule: whole run, groups of three, or one digit each |

The texts are written for this course (the Tâi-lô and Hakka spellings included — check them against your own usage; the Chinese paragraph and its translation are the same ones W4 demo 3 uses).

| Column | Source | What it demonstrates |
|---|---|---|
| GPT-2 | `tiktoken` `gpt2` | 2019 byte-level BPE, 50k vocabulary; digits `\p{N}+` |
| o200k | `tiktoken` `o200k_base` | the current GPT-series vocabulary (~200k); digits `\p{N}{1,3}` left to right |
| Llama 3 | `mlx-community/Meta-Llama-3.1-8B-Instruct-4bit` (tokenizer files only) | 128k vocabulary, tiktoken-style; `\p{N}{1,3}` |
| Qwen3.8 | `mlx-community/Qwen3.8-27B-4bit` | a vocabulary with a lot of Chinese; digits one at a time; its normalizer applies NFC |
| Gemma 4 | `mlx-community/gemma-4-26b-a4b-it-4bit` | ~260k multilingual vocabulary with byte fallback; digits one at a time |
| Mistral | `mlx-community/Mistral-7B-Instruct-v0.3-4bit` | 32k vocabulary, English-centred; most Han characters fall back to three byte tokens |
| Breeze | `MediaTek-Research/Breeze-7B-Base-v1_0` | Mistral's vocabulary plus ~30k Traditional Chinese tokens — the before/after pair with the Mistral column |
| bert-zh | `google-bert/bert-base-chinese` | 2018 WordPiece over a character vocabulary, no byte fallback: the one lossy column |
| ByT5 | nothing loaded | one token per UTF-8 byte: the upper bound for every byte-based tokenizer |

Keys during `show`: **Enter** fills the next row; **c** reads Qwen3.8's `config.json` and computes the embedding share $2Vd/N$ (the first row of the course's compute ledger); **l** lists the longest tokens containing Han characters in the o200k vocabulary; **q** quits.

## Requirements

| | |
|---|---|
| Packages | `transformers 5.17.0` (tokenizers only), `tiktoken`, `opencc-python-reimplemented` (for the Simplified row). All are installed by `../setup.sh`; on a non-Apple machine add `tiktoken opencc-python-reimplemented` to the manual install in `../README.md`. No `mlx`, no `torch` needed. |
| Downloads | `./present.sh fetch` fetches tokenizer files only (a few MB each) for six Hugging Face repositories and the two `tiktoken` encodings (cached in `../.tiktoken-cache/`). `mistralai/Mistral-7B-v0.1` is gated and optional (used by `inspect` only). Revisions are pinned in `../versions.lock`. |
| Device / memory / time | CPU; a few hundred MB; all nine tokenizers load in about 3 s. |
| Portability | should run anywhere the three packages install; tested only on an Apple M5 Max, macOS 26.6, Python 3.12.14 (2026-09-20). |

## Run it

```bash
cd demos                              # see ../README.md for creating .venv
cd w02_d1_fertility
./present.sh fetch                    # once, needs network: tokenizer files + tiktoken encodings; pins revisions
./present.sh inspect                  # per tokenizer: type, normalizer, pre-tokenizer regex, byte fallback, [UNK], NFC/NFD handling, digit rule, leading space, control tokens
./present.sh                          # the demo: Enter per row; c = ledger; l = longest Han-character tokens; q = quit
./present.sh rehearse                 # the whole table in one go → runs/rehearsal/table.json (also regenerates texts/zh_city_hans.txt with OpenCC)
./present.sh replay                   # the instructor's recorded table, row by row (marked as not live)
./present.sh fake                     # the screens with made-up numbers; nothing loaded
```

## What you should see

From `runs/rehearsal/table.json` and `inspect.json` (2026-09-20):

Token counts for the Chinese paragraph (209 characters, 627 bytes): GPT-2 **468** · o200k 193 · Llama 3 190 · Qwen3.8 **141** · Gemma 4 164 · Mistral **272** · Breeze 146 · bert-zh 209 (one per character) · ByT5 627 (one per byte). The same paragraph in Simplified: Qwen3.8 129, o200k 175, Mistral 244, **Breeze 176** — Breeze's added vocabulary is Traditional, so Simplified costs it *more* than Traditional does.

Cross-language cost (Chinese tokens ÷ English tokens for the same content): GPT-2 2.85 · Mistral 1.55 · o200k 1.19 · Llama 3 1.15 · Gemma 4 1.02 · Qwen3.8 0.86 · Breeze 0.83 · ByT5 0.83.

The Tâi-lô sentence, NFC vs. NFD: GPT-2 32 / 42, o200k 23 / 33, Llama 3 24 / 34, Gemma 4 26 / 31, Mistral 30 / 33 — and **Qwen3.8 24 / 24**, because its normalizer converts to NFC first (`inspect` shows `decode(NFD)` coming back as NFC). bert-zh is 17 / 17 for a different reason (its own normalization).

𠊎 (U+2028E): `[UNK]` on bert-zh (the Hakka row shows `unk: 2`), four byte tokens everywhere else — rendered as `<0xF0> <0xA0> <0x8A> <0x8E>` by the SentencePiece-style tokenizers and as four replacement glyphs by the tiktoken-style ones.

`1234567`: GPT-2 `123 | 45 | 67`; o200k and Llama 3 `123 | 456 | 7` (groups of three, **left to right**); Qwen3.8, Gemma 4, Mistral, Breeze one digit each; bert-zh `123456 | ##7`. This row is the setup for W2 demo 3.

The ledger key `c`: Qwen3.8-27B's `config.json` (`text_config`) gives $V = 248{,}320$, $d = 5120$, untied embeddings → embedding + output matrices ≈ 2.54 B of an estimated 24.4 B parameters, about 10 %.

**The `l` key list is not in the published record.** The `longest_cjk` entry of `table.json` was emptied before publishing: the twelve longest Han-character tokens in the o200k vocabulary are mostly lottery-spam and adult-site strings, which is itself the lesson — the vocabulary was learned from the web — but not something to keep in a course repository. Run `./present.sh` and press `l` to see them on your own machine.
